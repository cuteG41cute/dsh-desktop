> 给 UI 设计师的完整背景与页面清单。读完这份就能开始画图，不需要了解 DSH 内部实现。
> 相关技术方案见同目录 [project-migration-design.md](project-migration-design.md)；本文件只讲**界面、功能、关系、状态**。
> 版本：2026-11-19 · 对应管理器 3.6.x 之后的下一版功能（内部代号「项目迁移」）

---

## 1. 一句话说清这个产品

**dsh-manager 是 DeepSeek Harness（DSH）的桌面管理器**：它不聊天，负责管理本机的 DSH 实例——安装、启动、停止、修复、看日志，以及提供一些「不依赖实例的本地服务」（比如本地语音模型）。

- 现有平台：Windows（WPF/.NET 8）+ Linux（GTK3），**同一套设计语言，两套实现**；
- 用户画像：开发者本人（单一用户、重度使用），不是面向大众的产品；
- 现有界面：单窗口 + 左侧栏 + 三个页面（实例概览 / 管理器功能 / 管理器设置），浅色/深色两套主题。

## 3. 本功能要解决什么（用用户场景讲）

**场景 A：换电脑**
用户在 Windows 上做了一个项目，买了台 V100 服务器，想把项目搬过去继续。他需要：在管理器里选中项目 → 导出一个包 → 在新机器导入 → **打开会话能上滑看历史，接着聊，模型记得上下文**。

**场景 B：定期备份**
用户怕丢数据，想让管理器每天自动把几个项目备份到 D 盘某个文件夹，保留最近 N 份。

**场景 C：NAS 备份**
用户有 WebDAV NAS。他想勾选几个项目上传备份，换机器或误删后能从 NAS 拉回来。

**场景 D：从备份新建**
用户在本机删了项目但备份还在，想从备份里「新建」出一个项目继续用。

**场景 E：两台机器都聊过**
同一个项目在 A、B 两台电脑各自推进过。迁移后应该保留双方的对话，并在下次继续时让模型知道另一台机器上发生过什么（**交接摘要**）。

## 4. 信息架构（三级：实例 → 项目 → 备份）

```
管理器
├─ 实例列表（现有侧栏）
│   └─ 实例详情
│       ├─ 状态 / 端口 / 版本 / 启停（现有能力）
│       ├─ 【新】项目  ← 本功能主战场
│       │     ├─ 项目行（状态徽标、体积、会话数）
│       │     ├─ 导出…
│       │     ├─ 立即备份
│       │     ├─ 恢复…
│       │     └─ 从备份新建…
│       └─ 【新】备份
│             ├─ 备份计划（频率、目录、保留份数）
│             ├─ 备份历史
│             └─ WebDAV（服务器、勾选项目、上传/拉取）
└─ 【新】还有一个全局入口：「备份中心」？
      （见 §7 的待定项：是放实例详情里，还是独立页面）
```

**关键关系**：

```
实例 (Instance) ──1:N── 项目 (Project) ──1:N── 备份 (Backup)
     │                      │
     │                      ├─ 会话历史（可翻阅）
     │                      ├─ 项目文件（含隐藏目录）
     │                      ├─ 记忆库 / 文件历史（随项目走）
     │                      └─ 交接文件（跨设备时生成）
     │
     └─ 每实例有独立数据目录（项目不共享）
```

> 用户的心智模型：**备份和恢复都以「项目」为单位**，不以「实例」为单位；实例只是项目的容器。

### P1 实例列表（现有，仅微调）

- 现有实例行，需要在实例名称下增加一行小字：`3 个项目 · 12 个会话`（让用户知道点进去有什么）；

```

│ 地址：https://nas.example.com/dav   [测试连接]      │
│ 用户名 / 密码：                        ☐ 记住      │
```

- 上传中：每个项目一行独立进度（可并行/串行），可暂停；
- 失败：行内红字 + 重试按钮，不影响其他项目；
- 远端恢复：列出远端备份（项目名 / 设备 / 时间 / 体积）→ 选中 → 走 P4 的预览流程。

### P7 实例级「从备份新建项目」（新，流程页）

```
第 1 步：选来源
  ● 本地目录（选择文件夹）
  ○ WebDAV（列出远端备份）
第 2 步：列表（项目名 / 设备 / 时间 / 体积 / 会话数）
第 3 步：预览与目标目录
第 4 步：导入进度（同 P4）

```
> 设计要点：这是一个**向导流**（3–5 步），每步一屏或抽屉，不要堆成一页。

### P8 交接提示（可选，轻量）

当项目里存在「来自另一台设备的交接文件」时，在项目行/会话上显示一个小徽标：

```
📁 项目迁移设计   [⇄ 交接：来自 V100 · 11-19]
```
点开是一个只读说明卡：设备、时间、摘要前两行、`完整记录` 路径。
> 不需要设计大页面，一个徽标 + 弹层即可。

## 6. 关键状态（每页都要覆盖）

| 状态 | 表现 |
| --- | --- |
| 空 | 无项目 / 无备份 / 无 WebDAV 记录，各配一句引导 |
| 加载 | 骨架屏（项目行灰块），不要转圈整页 |
| 进行中 | 行内进度条 + 阶段文案 + 取消按钮 |
| 失败 | 行内红字 + `重试` + `查看日志` |
| 部分成功 | 顶部黄条：`2 个成功，1 个失败` + 展开详情 |
| 冲突 | 见 P4，默认「保留双份」，可改「跳过」 |
| 大项目 | 512 MB 以上提示耗时/流量 |
| 权限/空间不足 | 明确原因 + 建议（换目录/清理） |
| 离线 | WebDAV 不可达时禁用上传，保留本地备份可用 |

## 7. 交互与文案规范

### 7.1 文案语气

- 陈述句、专业、简短；不用感叹号，不用营销词；
- 按钮用动词：`导出`、`备份`、`恢复`、`从备份新建`；
- 危险动作二次确认：`恢复会覆盖当前项目，已自动导出当前状态作为备份。`；
- 时间用相对 + 绝对：`10 分钟前（10:42）`。

### 7.2 交互约定

- 所有长任务可取消；
- 破坏性操作前先自动导出（不经询问），并在结果里说明；
- 进度条不要假动画，按阶段推进；
- 备份/导入完成用 Toast，不弹大对话框；
- 列表行右侧按钮在悬停时显示，默认只留 `⋯`（减少视觉噪音）。

### 7.3 待和设计一起定的 3 个点

| 点 | 选项 |
| --- | --- |
| 备份能力放哪 | A. 实例详情内的「备份」标签页（推荐，上下文清晰）；B. 侧栏新增独立「备份」页（跨实例汇总） |
| 项目行密度 | A. 两行列表（推荐，信息全）；B. 卡片网格（更图形化，但项目多时占空间） |
| 「从备份新建」入口 | A. 实例详情顶部按钮；B. 空态引导 + ⋯ 菜单（两处都有也行） |

## 9. 设计交付要求

每个页面请出：

1. **浅色 + 深色**两套；
2. **空 / 加载 / 正常 / 错误**四态（至少项目列表和备份计划要全）；
3. **1280×800** 与 **1440×900** 两种宽度（管理器窗口最小 1100 宽）；
4. 组件清单：项目行、状态徽标、进度条、向导步骤条、勾选列表、对话框、Toast；
5. 交互标注：悬停/选中/禁用、按钮位置、点击后去哪；
6. 文案（可用占位，但结构要完整）。

**不需要设计**：DSH 自身的聊天界面（那是另一个产品）；不需要移动端。

## 10. 术语表

| 词 | 含义 |
| --- | --- |
| 实例 | 一个运行中的 DSH 服务（有端口、版本、独立数据目录） |
| 项目 | DSH 里的一个工作空间（一个文件夹 + 若干会话） |
| 会话 | 一段对话（可上滑看历史、可继续） |
| 备份包 | 一个 `.dshproj` 文件，含项目目录、会话、附件、注册表信息 |
| 设备戳 | 每台机器的唯一代号（如 `win-twinblade-a3f9`），出现在备份和交接里 |
| 交接 | 项目在另一台设备继续过后，留下的摘要与记录指针 |
| 保留份数 | 同一项目保留几个历史备份（1 = 只保留最新） |
