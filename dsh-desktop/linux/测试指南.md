# DeepSeek Harness 桌面版（Linux）测试指南

> 本指南供 Linux（deepin）电脑上的测试 agent 使用：按顺序执行测试项，
> 每项记录【实际结果】，全部完成后按「反馈模板」汇总回传。

---

## 0. 环境信息（先记录）

```bash
cat /etc/os-release | head -2
uname -m
python3 --version 2>&1 || echo "no python3"
node --version 2>&1 || echo "no node"
npm --version 2>&1 || echo "no npm"
curl --version 2>&1 | head -1 || echo "no curl"
```

---

## 1. 安装测试

### 1.1 deb 安装（主路径）

```bash
sudo apt install -y python3-gi gir1.2-webkit2-4.1 curl 2>/dev/null || sudo apt install -y python3-gi gir1.2-webkit2-4.0 curl
sudo apt install -y ./dsh-desktop_1.1.0_amd64.deb
```

【预期】安装成功，无报错；`dpkg -s dsh-desktop` 显示版本 1.1.0；
应用菜单出现「DeepSeek Harness」（deepin 20 若菜单未刷新，执行 `update-desktop-database ~/.local/share/applications` 或注销重登）。

### 1.2 tar 安装（备选路径，免 root）

```bash
tar xzf dsh-desktop-linux-1.1.0.tar.gz
cd dsh-desktop-linux
./install.sh
```

【预期】安装到 `~/.local/share/dsh-desktop/`；`~/.local/bin/dsh-desktop` 可用；
菜单出现「DeepSeek Harness」。

### 1.3 卸载测试（选做，卸载后可重装）

```bash
# deb 方式：
sudo apt remove -y dsh-desktop
# 或 tar 方式：
~/.local/share/dsh-desktop/uninstall.sh
```

【预期】程序文件、菜单项、图标被移除。

## 2. 首次启动：依赖自动引导

> 若目标机是**干净环境**（未装 dsh / node 版本 < 18），验证自动引导。

```bash
dsh-desktop --setup
```

【预期】依次出现询问：
1. 「缺少 GTK/WebKitGTK Python 绑定…是否自动安装系统依赖（sudo）」→ 回车同意（无 TTY 时自动执行，sudo 弹授权框）；
2. 「未检测到可用的 Node.js…是否自动下载安装 Node.js 22 LTS」→ 回车同意；
3. 「未检测到 DeepSeek Harness（dsh）…是否自动安装」→ 回车同意。

结束后 `dsh-desktop --setup` 再次运行应直接输出「依赖引导完成」，无任何询问。

非交互模式验证：`DSH_NONINTERACTIVE=1 dsh-desktop --setup`

## 3. 功能测试

> 以下测试前请先确认 DeepSeek Harness 已可用（若上一步自动安装了 dsh 即满足）。

### 3.1 首次启动完整链路

```bash
dsh-desktop
```

【预期】
1. 终端日志出现「启动 dsh web 服务（端口 3080）…」→「服务已就绪」→「打开桌面窗口: http://127.0.0.1:3080」；
2. 弹出 1440x900 桌面窗口，加载 DeepSeek Harness WebUI（窗口标题与网页标题一致）；
3. `curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:3080/` 返回 200；
4. 窗口内字体/图像清晰（无模糊）。

### 3.2 关闭窗口停止服务

关闭桌面窗口（点 X）后：

```bash
curl -s -o /dev/null -w '%{http_code}' --max-time 3 http://127.0.0.1:3080/ || echo "服务已停止"
ps aux | grep -c "[b]in.js web"
```

【预期】服务已停止（curl 失败或非 200；无 bin.js web 进程）。

### 3.3 服务已运行时再次启动

```bash
# 先手动启动服务：nohup dsh web >/dev/null 2>&1 &  （或先跑一次 dsh-desktop 再关窗前的状态下）
# 场景 A：服务在跑但无窗口
dsh-desktop
```

【预期】终端日志「服务已在运行，直接打开窗口」，不重复启动服务（`ps aux | grep "[b]in.js web"` 进程数不增加）。

### 3.4 单实例

窗口打开状态下再次执行 `dsh-desktop`：

【预期】日志「已有实例在运行（/tmp/dsh-desktop.lock），退出。」，不弹新窗口。

### 3.5 多会话拖拽分离窗口（核心功能）

在 WebUI 左侧会话列表中：
1. **按住一个会话**（非当前会话），**向右拖出侧边栏**（拖到主区域）松手；
【预期】弹出**新窗口**显示被拖出的会话；原窗口保持当前会话。
2. **按住当前会话**拖出侧边栏松手；
【预期】新窗口显示该会话；**原窗口切换为「新会话」界面**。
3. 在新窗口中再次拖出另一个会话；
【预期】可继续开新窗口（多窗口并存）。
4. 把会话拖回列表内松手；
【预期】不弹窗（触发的是原有排序功能）。
5. 关闭分离出的子窗口；
【预期】仅子窗口关闭，主窗口与服务不受影响。

### 3.6 手动指定 dsh 路径（DSH_BIN）

```bash
DSH_BIN=/path/to/your/dsh/lib/bin.js dsh-desktop
```

【预期】优先使用指定路径；路径不存在时日志出现「警告：DSH_BIN 指向的文件不存在」。

### 3.7 自定义端口

```bash
# 若 3080 被占用：先启动 dsh 在 8080：nohup dsh web --port 8080 >/dev/null 2>&1 &
DSH_WEB_URL=http://127.0.0.1:8080 dsh-desktop
```

【预期】窗口加载 8080 端口页面；启动器探测/拉起服务使用 8080。

### 3.8 图标与菜单

【预期】应用菜单中的图标为自定义图标（蓝/深色 Logo）；
窗口标题栏图标一致；`/usr/share/icons/hicolor/256x256/apps/dsh-desktop.png` 存在（deb 安装）。

## 4. 已知差异（非缺陷）

- Linux 无系统托盘：关闭主窗口 = 退出程序（服务随启动器停止）；
- 单实例重复启动仅提示退出（不唤起已有窗口）。
