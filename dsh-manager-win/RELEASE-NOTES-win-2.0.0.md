# dsh-manager Windows 2.0.0

这是管理器第一次**大版本**更新。1.0.x 时代它是一个「壳」：借系统的 node/npm、把实例当子进程、界面靠一张位图缩放。2.0 把三件事都换了底座。

## 一、实例：从「npm 装一个包」变成「独立的仓库检出」

| | 1.0.4 | 2.0.0 |
| --- | --- | --- |
| 来源 | `npm install @deepseek-ai/dsh` | `git clone` 官方仓库（可选 tag），实例内装 pnpm 后 `pnpm install` + `pnpm run build` |
| Node | 用系统的，或在实例里放一份便携版 | **必须**便携 Node（`<实例>\node`），版本可选 |
| pnpm / store | — | 都在实例目录（`<实例>\tools`、`<实例>\pnpm-store`） |
| 数据目录 | 全局 `%USERPROFILE%\.dsh`（**所有实例共享**工作区/插件） | 每实例独立 `<实例>\dsh-home`（新实例为全新空目录） |
| 卸载 | 删目录 | 删目录（停服务 → 删目录 → 移出登记表，一条龙） |

代价说清楚：一个源码实例约 **4.25 GB**，首次安装 clone ≈1 分钟 + `pnpm install` ≈2 分 + `build` ≈6 分。

## 二、运行时：服务不再挂在本管理器的进程树上

1.0.x 用管道抓 node 的 stdout，于是**管理器一崩、实例跟着 EPIPE 退出**（而且日志中文全是乱码）。2.0 改为：

```
生成 <日志目录>\<实例>.run.cmd  →  chcp 65001 & node ... >> 日志 2>&1
```

输出是**文件句柄**而不是我们的管道 —— 管理器退出、崩溃、被任务管理器杀掉，实例照常运行；日志也变成正确的 UTF-8。停止/启动/重启只发指令，界面只如实显示状态。

## 三、界面与交互

- **拖动缩放**：关掉 WPF 分层窗口（那是软件渲染），拖动期间不重排、摘掉 8 个软件阴影、文字临时灰度；再升级为**矢量缩放**（Canvas + RenderTransform，斜角锁宽高比，按拖拽方向预置缩放算式），帧时间 **60–76ms → 14–15ms**。
- **启动**：扫描 6.2 秒 → **0.34 秒**（原来对 20 个端口逐个 TCP 连接、每次等 300ms 超时；改成一次 `netstat` 拿「端口 → PID」整表）。
- **四角圆角**用 `SetWindowRgn` 按设计半径裁窗口，启动即生效。
- **常用功能**改用 `UniformGrid`：只有 4 / 2 / 1 列三档，每行必然铺满。
- 最近日志只显示最新 15 条；状态徽标跟随真实运行状态；托盘图标取 exe 内嵌图标（修掉句柄失效导致的静默崩溃）；单实例启动会把藏在托盘里的旧窗口捞出来；UI 线程异常只记日志不再退出。

## 四、检查更新 / 查看 Token

- **版本选择窗口**：先弹窗、列表异步加载（顶部 DSH 风格转圈），dsh 与 Node 各一个抽屉下拉，第一项是「保持当前（x.y.z）」，**支持升级与降级**；底部「检查更新」可随时重拉。
- 修掉「版本检测把 0.0.1 当最新」（`npm view versions` 是旧→新数组，之前取了第一个）。
- **查看 Token**：独立主题窗口，显示访问地址 / 本次启动 token / 带 token 地址 / 认证 cookie / 当场校验结果（200/401），并支持「重新获取 token」「复制带 token 地址」。

## 升级须知

- 覆盖 `DshManager.exe` 即可（或 `install-win.ps1`）。已有的旧实例（没有 `dsh-home` 的）继续走全局 `~/.dsh`，**不会被强制迁移**。
- 想彻底隔离某个老实例：停服务 → 把 `~/.dsh` 的 `sessions/storages/profiles` 复制到 `<实例>\dsh-home` → 再启动。
- 源码实例首次启动后，模型凭据要在它自己的设置里重新填一次（`dsh-home` 是全新的）。
